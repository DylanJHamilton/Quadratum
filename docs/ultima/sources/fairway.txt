1. HIGH: BASIC SPLIT CONTENT OVERLAPS IMAGE AND COPY ON MOBILE
Section: split-content-dynamic.liquid
Reproduction: Use stacked mobile presentation, image first, min-height 40vh, a multi-line heading, a paragraph and a button. View at 390 x 844.
Observed: The image and text overlap. In the Buying Guides feature, the row was 337.6px tall; its image occupied 240px; the content side shrank to 97.6px while its inner copy required 436.3px. The vertically centered copy began over the image and extended beyond its assigned space.
Expected: Image and copy stack without overlap; the section grows to fit its text and button.
Code evidence: lines 335-344 set the row's minimum height and give columns flex:1 1 0 with min-height:0. Line 347 gives the image a 240px minimum. Line 369 vertically centers the panel's contents.
Suggested repair: Let stacked mobile columns size from content, keeping equal-height flex distribution for desktop only. Verify long headings, multiple paragraphs, buttons, image-first/image-last, and mobile background mode.
Fairway workaround: Replaced the About story and featured Buying Guide with native Featured Product Hero panels. No custom code was added.

2. HIGH: FOOTER FIVE DEPARTMENT HUB IGNORES RESPONSIVE COLUMN RULES
Section: footer-five.liquid
Reproduction: Choose Department hub, add several footer blocks, and switch to tablet/phone widths.
Observed: The layout-specific desktop grid rule keeps multiple narrow columns instead of allowing the responsive grid to stack, producing cramped mobile footer content.
Expected: Tablet column settings apply and the phone layout stacks into one column.
Code evidence: lines 181-182 use #FooterFive-ID.q-footer-five--layout-department_hub .qf5__grid. This selector is more specific than the tablet rule at lines 600-602 and the phone rule at lines 636-637, so its desktop column count wins.
Suggested repair: Scope the Department hub desktop override to its intended breakpoint or match its specificity in the responsive overrides. Test all Footer Five layout variants with long links and newsletter blocks.
Fairway workaround: Used the native Marketplace layout, which stacks correctly.

3. MEDIUM: COLLECTION CLASSIC ACTIVE PRICE CHIP SHOWS RAW CENTS
Section: main-collection-classic.liquid
Reproduction: Enable active filter chips. Set maximum price to 9000 and apply the filter.
Observed: The results are correctly limited to products at or below $9,000, but the chip displays Price:0–900000.
Expected: A readable, localized currency range such as $0–$9,000.
Code evidence: the active price chip at lines 665-670 prints filter.min_value.value and filter.max_value.value directly without a money formatter.
Suggested repair: Apply appropriate Shopify currency formatting to both bounds, including open-ended ranges. Test zero, minimum-only, maximum-only, and multiple currency formats.
Fairway workaround: Disabled active filter chips through the section setting. Price filtering, ascending sorting and the drawer's clear controls remain available.
